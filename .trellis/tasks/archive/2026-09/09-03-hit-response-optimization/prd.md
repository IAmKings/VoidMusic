# 击打触发手感优化

## 目标

让 Void Music 的空中击打更贴手：减少 MediaPipe 结果在色块分割后的等待，消除快速连续拍打的 250 ms 人为限制，并避免过期手部结果或过期鼓区造成延迟、漏击和错击。

## 已确认事实

- 当前 `HandTracker` 已输出未平滑的 `TimestampedHands`，命中路径不会受到骨架 One-Euro 平滑的拖慢。
- 命中处理在 `FrameRouter` 的色块消费者中执行；该消费者会同步分割，且分割每三帧执行一次，因此 MediaPipe 已完成的结果仍可能等待分割与下一次相机分析。
- 当前手部结果队列容量为 4；在约 15 FPS 的实测条件下，旧结果理论上可落后约 267 ms。
- `HitDetector` 以单个相邻帧的向下速度生成候选；当前 110 ms 复位要求“冷却结束”和“当前帧正在抬手”同时成立，提前发生的抬手会被遗忘。
- `HitArbiter` 对同一鼓区另有 90 ms cooldown；它不阻止换色，但候选生成前的单指复位会同时影响同色和换色击打。
- 最近真机 UI 显示分析 FPS 约 16；此前基线的分割 P95 为 39 ms、鼓区缓存年龄 P95 为 134 ms。
- 约 16 FPS 且每三帧分割一次时，鼓区刷新周期约 188 ms，叠加分割耗时后会超过当前 180 ms 有效期，形成周期性不可击打窗口。
- Oboe 的触发队列无锁，但队列满时会在 native 层静默丢弃，Kotlin 和 HUD 不可见。
- PJZ110 连续演奏现场的手部源帧延迟达到 P50 186 ms / P95 208 ms；固定 140 ms 门限会把后续结果全部丢弃，而 Oboe 后端仍正常、丢音计数为 0，表现为连续击打后完全无声。

## 需求

- P0：MediaPipe 回调完成后，将 Tap 模式的手势→鼓区→音频提交移入独立的顺序命中通道；不得等待 OpenCV 分割完成。Compose 只能接收不可变事件，不能在视觉回调线程读取 Compose 状态。
- P1：把 `HitDetector` 改为“下拍触发、记住抬手、冷却后复位”的状态机；保持单帧低延迟触发，同时用迟滞防止连续下降期间反复触发。默认快速连击复位时间为 60 ms，覆盖 90–160 BPM 十六分音符。
- P1：默认击打速度阈值调整为 0.50，同鼓区重复触发间隔调整为 70 ms；已有安装中的旧默认值必须迁移到当前调音版本，自定义设置仍可重新调整。
- P2：只处理新鲜手部结果和新鲜鼓区快照；手部结果以 140 ms 为理想目标，按设备近期推理基线加 40 ms 抖动余量自适应，但不得超过 260 ms 硬上限；鼓区源帧到消费超过 260 ms 时安全跳过。
- P2：平衡档手部分析目标提升到 24 FPS，颜色分割继续按三帧子采样运行，避免用骨架平滑参数掩盖触发延迟。
- P2：暴露当前音频后端和 native 触发队列丢弃数；不得改变回调线程的无锁、无分配预算。
- 保持步进模式的格子切换、现有 HSV 识别、手部显示平滑、离线能力和 API 26+ 兼容性。

## 验收标准

- [ ] 命中快速通道在色块分割发生时仍能消费手部回调；真机 `回调→消费` P95 相比现有串行路径明显降低，目标 ≤ 15 ms。
- [ ] 连续单指有效下拍间隔 94–167 ms 可各触发一次；提前抬手不会丢失，单次连续向下运动及静止抖动只触发一次。
- [ ] 同色连击和不同颜色轮击使用同一离散下拍语义，不引入跨颜色全局等待。
- [ ] 突发陈旧手部结果会被拒绝，持续 186–208 ms 的设备推理基线仍可连续击打，超过 260 ms 的手部结果和鼓区快照不会触发；约 16 FPS、每三帧一次的正常静态鼓区持续可击打。
- [ ] HUD 显示音频后端与队列丢弃数；原生队列满时计数增加，普通演奏保持 0。
- [ ] 命中状态机、过期丢弃、快速通道和音频观测均有 JVM 测试；现有测试、Lint、debug 构建通过。
- [ ] PJZ110 上完成红/蓝/绿/黄物件、单指快速连击、双手交替、步进模式与后台恢复手动复测。

## 不在本轮范围

- 更换 MediaPipe 模型、训练专用手势模型、声学出声延迟测量、改变 Oboe 的混音算法。
- 重新设计色块 ROI 或分割执行器；仅将命中通道从其串行等待中解耦。
