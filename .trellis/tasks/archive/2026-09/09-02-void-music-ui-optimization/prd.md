# Void Music UI 优化

## Goal

将 Void Music 的主演奏界面从“同时暴露全部调试/调参控件”调整为“沉浸式演奏优先”：扩大相机与鼓区的可视面积，降低现场操作干扰，同时保留可发现、可用的 HSV 调参、校准和设置入口。

## Confirmed Facts

- 当前真机主界面包含相机预览、实时击打/步进序列模式切换、检测状态、鼓区覆盖层、校准/设置入口、颜色选择和 HSV 区间控件。
- HSV 与颜色控件长期占据屏幕下半部；校准/设置悬浮按钮与实时内容存在重叠；颜色标签横向裁切，现场演奏的可视区域不足。
- 项目采用 Kotlin + Jetpack Compose，当前产品色彩为浅紫与橙色，主界面已在实体设备上运行。
- 本轮不改变相机、手部追踪、击打、音频、序列器或持久化的业务语义。

## Requirements

- 主演奏态以取景器、鼓区、模式切换与必要状态为第一优先级，避免高级调参默认遮挡现场。
- HSV、颜色选择、校准与设置必须可发现、易撤销，并在窄屏上不产生裁切或遮挡关键控制。
- 交互状态（当前模式、选中颜色、检测状态、音频/播放状态）需要有清晰的视觉层级与足够对比度。
- 引导页仅在首次启动时显示；用户完成或跳过后，后续启动直接进入主界面，并可从设置页主动重新查看使用指南。
- 保持中文界面、无障碍语义、现有视觉识别覆盖层和 API 26+ 兼容性。
- 改造后的 Compose UI 必须通过现有构建、单元测试和静态检查；应在真机核对实时击打与步进编辑入口仍可使用。

## Acceptance Criteria

- [ ] 默认实时击打界面中，相机预览与鼓区覆盖层占据主要可视区域；高级 HSV 控件不默认遮挡。
- [ ] 颜色选择不被裁切，当前颜色与鼓声映射可在单手范围内切换。
- [ ] 校准、设置与 HSV 调参可从主界面进入并返回，不丢失当前会话状态。
- [ ] 实时击打、步进序列和播放控制在视觉与操作上均可识别。
- [ ] 真机截图确认窄屏布局无重叠、无裁切、文字可读；构建、单元测试与 Lint 通过。
- [ ] 完成或跳过引导后强制重启应用，不再出现引导；设置页可重新打开引导。

## Out of Scope

- 新增音色、手势、算法或导航目的地。
- 改变品牌名称、应用身份或发布签名。
- 重做设置页中与本次主界面无关的业务项。

## Visual Direction

- 采用“明亮创作工具”方向：保留浅紫＋橙色的品牌记忆，以更克制的中性表面承载控制，确保相机画面上的文字与状态在明亮环境下仍清晰可读。
- 不切换为深色舞台风格，避免重建整套色彩与可读性基线；沉浸感主要通过减少常驻参数面板、强化全屏取景器和控制层级实现。
