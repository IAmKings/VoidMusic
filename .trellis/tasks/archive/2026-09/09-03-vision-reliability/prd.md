# 视觉识别可靠性优化

## Goal

提升 Void Music 在真实桌面演奏中的物品分区、手部追踪与击打链路可靠性，优先消除时序错配、原生资源压力和性能档位失效问题；保持本地离线、彩色物件交互和现有 MediaPipe/OpenCV 技术路线。

## Confirmed Facts

- 物品识别是 HSV 颜色分割，不是通用语义物体识别；适用目标为颜色鲜明的贴纸、纸块和玩具。
- 手部关键点使用 MediaPipe HandLandmarker 的 LIVE_STREAM 异步回调；当前击打路径在相机帧中读取最近手部结果，结果时间与当前帧时间未绑定。
- HSV 形态学核在每个预设、每次分割时创建，未显式释放；性能配置中的 `analysisFrameCap` 尚未接入帧路由。
- 当前鼓区命中基于外接矩形、额外边距和中心吸附；STEP 模式没有把候选击打与具体手指绑定。
- 尚无覆盖真实 MediaPipe 异步时序、OpenCV 长时资源、光照和三档设备性能的完整验收数据。

## Requirements

- 手部结果、源帧时间戳和击打候选必须来自同一条时序链路；不得以较旧的异步手部结果配对当前相机帧时间。
- OpenCV 的原生资源必须有明确、可关闭的生命周期；持续演奏不得因临时 Mat 累积造成内存压力。
- 高/中/低性能档位必须实际限制分析提交频率，并保留 CameraX 的最新帧策略。
- TAP 命中应优先选择最接近候选点的有效鼓区；STEP 必须使用产生候选的同一手指位置。
- 取色应避免边缘背景把 HSV 范围过度放宽；重叠预设须有可预期的结果。
- 保持 API 26+、离线处理、既有声音映射与 UI 回调契约。

## Acceptance Criteria

- [ ] 异步手部结果携带源帧时间戳；击打速度、候选点和时间戳不再混用不同帧。
- [ ] 形态学 kernel 被复用或显式释放；关闭分割器后无可继续使用的原生资源。
- [ ] `analysisFrameCap` 在 HIGH/MEDIUM/LOW 实际生效，并有纯逻辑测试覆盖节流边界。
- [ ] 两个重叠可命中的鼓区选择距离候选点最近者；STEP 使用候选点而非手列表首项。
- [ ] 取色使用稳健样本统计，空样本/低饱和/背景混入场景有测试。
- [ ] JVM 测试、Lint、debug APK 构建通过；真机记录分析 FPS、MediaPipe 结果 FPS、分割耗时、鼓区缓存年龄和击打到出声延迟。

## Out of Scope

- 将彩色物件分割替换为云端或通用语义物体识别。
- 更换 MediaPipe 手部模型、增加深度传感器依赖或改变音频引擎。
- 未经数据集与产品决策支持的自训练检测模型。
