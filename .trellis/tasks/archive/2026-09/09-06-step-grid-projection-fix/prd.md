# 修复步进序列网格投影与校准流程

## Goal

恢复步进序列模式的核心可用性：用户完成四点校准后必须看到并可操作完整的
4×16 网格；未校准时不得出现“节拍已启动但画面为空”的状态。

## Requirements

- 投影创建不得依赖未初始化时序，也不得把所有失败静默折叠为无提示的空画面。
- 校准界面必须预览完整 4×16 网格，并提供明确的“确认并保存”操作；默认角点无需拖动即可保存。
- 无有效校准时，步进页必须显示可行动提示；点击播放不得启动 Transport，而应引导用户校准。
- 有效校准保存后，步进网格必须立即显示，冷启动后从 DataStore 正确恢复。
- 现有实时击打、STEP 节拍/BPM/清空、手势切换、相机和音频行为不得退化。
- 投影计算仍是校准时的一次性工作；绘制和逐帧命中路径不得引入 Mat 分配或额外同步 I/O。

## Acceptance Criteria

- [x] 默认矩形和合理透视四边形均能产生 4 行 × 16 列、共 64 个有效单元中心；退化或自交四边形被拒绝。
- [x] 无校准进入 STEP 时显示“请先完成四点校准”，点击播放不会进入播放状态并打开校准入口。
- [x] 校准界面首次打开即可看见 64 格预览，直接确认默认角点后主界面立即显示网格。
- [x] 拖动角点后确认可保存；取消不会覆盖上一次有效校准；非法角点显示错误且不退出。
- [x] 校准和序列重启后恢复，播放游标、单元开关、BPM 与清空功能正常。
- [x] JVM 投影/状态测试、Compose UI 测试、Lint、Debug 构建全部通过。
- [x] PJZ110 真机连续三次完成“清除校准 → STEP → 播放引导 → 确认校准 → 显示网格 → 启动”，且冷启动后网格仍存在。

## Out of Scope

- 不调整步进节拍算法、音色映射、击打阈值或相机性能档位。
- 不新增网格模板、曲目管理、导出或分享功能。
