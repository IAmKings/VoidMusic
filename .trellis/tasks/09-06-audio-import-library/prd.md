# 用户音频导入、校验与音色库迁移

## Goal

让用户能够在 Void Music 内通过系统文件选择器导入短 WAV 采样、组成可演奏的自定义音色，并在重启、离线、前后台切换和应用升级后继续可靠使用；任何导入、校验或切换失败都不得破坏当前可发声的音色。

## Confirmed Facts

- 当前内置音色由 `BuiltInKits` 静态提供，运行时不依赖 Room。
- 旧 `KitDatabase` 只保存内置音色摘要，数据库名仍为 `ods_kits.db`，没有用户数据和正式迁移历史。
- `Settings.activeKitIndex` 依赖列表位置，加入、删除或重排自定义音色后可能指向错误对象。
- `SampleRef` 只能表达 `res/raw`；`DrumEngine` 和 SoundPool 后端均不能加载应用私有目录中的音频。
- 当前 `WavDecoder` 只支持 PCM16 单/双声道，并且没有完整验证 chunk 边界、声明长度和采样率。
- 当前 `DrumEngine.setKit()` 会先停止旧后端再加载新音色，失败时无法保证旧音色继续可用。
- 应用为本地优先，不需要网络权限或云端服务。
- 已批准 MVP 只支持 WAV；MP3/M4A、云同步、收藏、标签和复杂音效参数不在本轮范围。
- 架构参考来自已归档任务的 `research/audio-import-storage-and-migration.md`。

## Requirements

### R1 — MVP 用户流程

- 设置页提供“自定义音色”入口；用户可从当前音色复制创建一个自定义音色，并编辑名称。
- 用户为五个鼓垫分别选择 WAV 文件；未替换的鼓垫继续引用复制来源的有效采样，保证新音色始终完整可演奏。
- 文件选择使用 Android Storage Access Framework，不申请广泛文件访问权限。
- 自定义音色可选择、重命名和删除；内置音色不可删除。
- 导入、校验、保存和切换必须显示明确的进行中、成功或失败状态，禁止静默失败。

### R2 — 输入限制与校验

- MVP 接受 RIFF/WAVE、PCM 16-bit、单声道或双声道文件；实际内容而非 MIME 或扩展名是最终判定依据。
- 单文件最大 10 MiB、最长 5 秒；复制过程中超过大小限制立即停止。
- 支持 8,000–96,000 Hz 输入并规范化为音频引擎的统一采样率；不得只修改 WAV 头伪装重采样。
- 必须验证 RIFF/WAVE、`fmt ` 与 `data` chunk、奇数 padding、声明长度、块边界、帧对齐和非空音频。
- 文件名、URI 和文档提供者元数据视为不可信输入；错误必须映射成稳定、可本地化的产品错误。

### R3 — 存储与原子性

- 导入内容先流式复制到 `filesDir/audio-import-staging/`，同时执行大小限制和 SHA-256 计算。
- 校验与规范化成功后，使用不可冲突的相对 `storageKey` 原子移动到 `filesDir/audio-assets/`。
- Room 只保存音色、音频资产和鼓垫映射元数据，不保存 BLOB、完整 PCM、绝对路径或临时 URI。
- `import` 成功返回时，正式文件、资产记录和映射必须同时可用；任一步失败都回滚且保留原音色。
- 相同规范化内容按 SHA-256 去重；删除音色不得删除仍被其他音色引用的资产。

### R4 — 正式数据模型与迁移

- 建立新的正式音色库数据库基线，启用 `exportSchema=true` 并提交 Schema 历史。
- 旧 `ods_kits.db` 没有用户数据，不迁移其内置摘要；新库不得依赖每次启动写入内置音色。
- Room 模型至少覆盖 Kit、AudioAsset、KitPadMapping，并用外键、唯一约束和事务保证一致性。
- `Settings` 新增稳定的 `activeKitId`；首次读取旧设置时由 `activeKitIndex` 映射到对应内置音色 ID，找不到时回退默认音色，并写入迁移版本。
- 导入功能发布后禁止 destructive migration。

### R5 — 播放与切换

- `KitLibrary` 是 UI、Room 和文件系统之间的唯一业务入口；DAO 和绝对路径不得暴露给 UI 或 `DrumEngine`。
- 内置音色与 Room 中的自定义音色合并为稳定 ID 的只读目录。
- 文件读取、哈希、校验、解码、重采样和 Room 查询不得发生在主线程或原生音频回调线程。
- 新音色所有鼓垫准备完成后才允许切换；准备或后端启动失败时旧音色继续发声。
- Oboe 与 SoundPool 后备路径都必须支持导入音色，并保持现有音量、连续击打和路由恢复行为。

### R6 — 启动协调与删除

- 启动时轻量清理过期 staging 文件，并标记记录存在但正式文件缺失的资产为 BROKEN。
- 只删除能够证明无引用的孤儿文件；不得在启动主路径执行大规模哈希、解码或转码。
- 删除使用 `PENDING_DELETE` 状态：先解除音色引用，再删除文件，最后删除资产记录；失败可在下次启动重试。
- 当前活动音色被删除或损坏时自动回退默认内置音色，并持久化正确的 `activeKitId`。

### R7 — 兼容与质量

- 现有内置音色、设置、引导、TAP、STEP、Oboe 恢复和 SoundPool 降级行为不得退化。
- 所有迁移、解析、事务回滚和资源共享删除规则必须有自动化测试。
- 签名 Release 必须在真机完成导入、切换、离线重启、后台恢复与删除回退验证。

## Acceptance Criteria

- [x] 旧设置中的两个合法 `activeKitIndex` 均迁移到正确的内置 `activeKitId`；非法值回退 `default`，迁移只执行一次。
- [ ] 新音色库 Schema 已导出；Room 测试已覆盖创建、外键、联合唯一约束、事务回滚和共享资产删除，待测试包真机执行后确认。
- [ ] WAV 测试覆盖未知 chunk、奇数 padding、截断/伪造长度、缺失 chunk、错误编码、空数据、单/双声道和支持采样率边界。
- [ ] 超过 10 MiB 或 5 秒的文件被拒绝，staging 文件被清理，Room 和正式目录无残留。
- [ ] 同一内容重复导入只保留一个音频资产文件；删除其中一个音色不影响另一个音色播放。
- [ ] 导入中断、数据库写入失败、磁盘空间不足或正式移动失败时，原活动音色继续发声且状态可恢复。
- [ ] 用户可复制、命名、编辑、选择和删除自定义音色；内置音色保持可选且不可删除。
- [ ] 所有鼓垫准备成功后一次性切换；损坏或缺失资产不能进入可播放目录，失败后旧音色仍可演奏。
- [ ] Oboe 和 SoundPool 均能播放导入音色，快速同色连击与跨颜色切换无新增漏声或明显过渡期。
- [ ] 应用离线重启及后台恢复后，自定义音色、鼓垫映射和活动音色选择保持正确。
- [ ] Debug 单元测试、Lint、Room/仪器测试和签名 Release 构建通过，真机导入与演奏验收通过。

## Out of Scope

- MP3、AAC、M4A、FLAC 等非 WAV 输入。
- 云同步、跨设备同步、社区音色商店和网络下载。
- 收藏、标签、搜索、批量导入和音色包导出。
- 波形编辑、裁剪、淡入淡出、破坏性响度归一化和多层力度采样。
- 将音频文件或解码 PCM 保存为 Room BLOB。

## Product Defaults

- 首版采用“复制当前音色后逐鼓垫替换”的流程，避免半成品音色进入可播放目录。
- 初始限制采用 10 MiB / 5 秒；后续只能通过有数据支持的独立产品调整修改。
- 规范化输出使用 PCM16 单声道 WAV；统一采样率由音频实现阶段依据 Oboe 输出契约固定并用测试保护。

## Notes

- 本任务优先保护数据一致性和当前演奏连续性，再增加管理 UI。
- 高/中/低真机与 20 分钟稳定性属于正式发布前性能门禁，不在本任务重复定义。
