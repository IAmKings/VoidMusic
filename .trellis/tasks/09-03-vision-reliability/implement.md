# 视觉识别可靠性优化 — 实施计划

1. 建立时间戳化的手部结果契约，修复异步结果与当前帧混用；同时复用/释放 OpenCV morphology kernel。
2. 在 FrameRouter 接入每档 `analysisFrameCap`，补充提交/丢弃/结果速率指标和纯逻辑测试。
3. 让候选点驱动 STEP，收紧 TAP 的重叠鼓区选择；改进取色样本统计与边界测试。
4. 运行 JVM 测试、Lint、debug 构建；在真机按高/中/低档执行识别、延迟、稳定性验证。

## 执行顺序

- 第一批只修复时序与资源生命周期，不改变 HSV 预设或手势阈值。
- 第二批落实性能配置并在同一设备回归，避免节流掩盖正确性问题。
- 第三批调整命中和取色，使用固定场景样本验证误触没有增加。
- 第四批根据真实数据决定是否需要更激进的模型或算法升级。

## 执行记录（2026-09-03）

- `HandTracker` 的原始结果改为有界 `TimestampedHandsQueue`：每个结果保留 MediaPipe 回调的源帧时间戳，`MainScreen` 逐个消费队列并以该时间戳更新 `HitDetector`，不再用当前相机帧时间配对旧结果。
- `ColorSegmenter` 现在复用单一 morphology kernel，实现 `close()` 并在页面重建/销毁时关闭；分割内的 Mat、mask、contour、hierarchy 与下采样 Bitmap 都有明确释放路径。
- `FrameRouter` 在位图转换前应用 `analysisFrameCap`，已接入 HIGH/MEDIUM/LOW 的 30/20/15 FPS 上限；被节流帧只关闭 `ImageProxy`，不触发复制、旋转或推理。
- 重叠扩展鼓区按候选点到中心的距离选择；STEP 使用 `HitCandidate.point` 定位格子。取色限制为中心圆形区域，忽略低饱和样本并用 10/90 分位数计算 S/V 范围。
- 定向时序/节流测试、完整 `testDebugUnitTest` 与 `lintDebug` 通过；debug APK 构建通过。
- 真机（PJZ110）已重新连接并完成最新 debug APK 覆盖安装。应用可稳定进入实时击打页；空场景显示 0 个物件、0 只手，分析 FPS 为 15，近期日志未发现应用崩溃或 `HandTracker`、`ColorSegmenter`、MediaPipe 异常。此次仅验证启动与空场景链路，尚未替代有彩色目标和真实手部动作的识别/延迟/20 分钟稳定性复测。
