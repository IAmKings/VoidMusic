# 运行性能与稳定性优化

## Goal

在不改变现有点击、色块切换和四种鼓声演奏手感的前提下，治理 Void Music 的运行生命周期、步进网格计算、音频恢复、状态一致性和图像内存压力，使应用能够稳定完成前后台切换、音频路由切换和长时间演奏。

## Confirmed Facts

- 当前实时链路为 CameraX → FrameRouter → HandTracker/ColorSegmenter → TapHitProcessor → DrumEngine。
- 相机已使用最新帧背压策略；击打使用原始手部结果，界面使用平滑结果。
- 当前单元测试与 Lint 通过，Lint 为 0 errors、80 warnings。
- CameraModule 的分析 Executor 没有最终关闭路径。
- GridScanner 会在界面绘制或重组期间重复创建透视矩阵和逐点 Mat。
- Oboe 断开后仅记录日志，没有自动重建或降级状态机。
- MainScreen 同时承担资源创建、线程桥接、识别编排、击打、音频、持久化和界面绘制。
- Transport 的网格包含可变列表，节拍循环使用相对 delay。
- 运行时节能降档会覆盖持久化的用户性能档位。
- Room 音色数据库目前只写入内置音色元数据；生产界面和音频链路直接读取 BuiltInKits。

## Requirements

### R1 — 运行生命周期

- 只有在相机权限有效且主演奏页面处于前台时，才运行 CameraX、MediaPipe 和图像分析。
- start、suspend、resume、stop、close 必须幂等，并拒绝过期的异步相机绑定结果。
- CameraModule 最终关闭时必须释放分析 Executor。
- 前后台恢复不得改变用户当前模式、音色、音量、BPM 和校准结果。

### R2 — 步进网格投影

- 透视矩阵与 64 个格子中心仅在四个校准点发生变化时重新计算。
- Compose 绘制期间不得修改 GridScanner，也不得逐格创建 OpenCV Mat。
- 识别线程和界面线程共享不可变的 GridProjection 快照。

### R3 — 音频连续性

- Oboe 断线时必须向 Kotlin 层暴露状态并自动尝试重建。
- 重建失败时自动降级到 SoundPool；恢复过程不得要求重启应用。
- 暴露当前后端、ready、丢弃触发数和 xRun/underrun 指标供验收采集。
- Voice 抢占策略不得固定抢占同一 Voice。

### R4 — 演奏流程边界

- 从 MainScreen 抽出单一的 LivePerformancePipeline/Controller，集中管理实时资源和跨线程快照。
- MainScreen 只负责权限、导航、用户操作和状态渲染。
- 删除已经不可达的旧 TAP 击打分支，保留 TapHitProcessor 作为 TAP 模式唯一入口。
- 不引入依赖注入框架；优先使用构造参数和小型不可变数据类型。

### R5 — 节拍与状态一致性

- SequenceState 不得暴露 MutableList；64 格内部状态优先使用 Long 或等价不可变结构。
- Transport 使用单调时钟和绝对截止时间，处理耗时不得累计为长期 BPM 漂移。
- BPM、播放、停止、清空和步进切换必须可用虚拟时钟测试。

### R6 — 性能策略与持久化

- 分离用户首选档位和运行时节能/温控限制，限制解除后恢复用户档位。
- 使用 PowerManager 热状态监听，不从省电广播读取不存在的热状态。
- 生命周期感知地收集 Compose 状态。
- 高频滑块调整在拖动结束或合并后持久化，避免每一帧写 DataStore。

### R7 — 图像与分割性能

- 先采集 Bitmap 分配、GC、手部分割耗时、色块分割耗时和温升基线，再决定复用范围。
- Bitmap/MPImage 的释放必须符合 MediaPipe 异步所有权，不允许为降低分配而引入 use-after-close。
- 色块分割可采用空闲低频、场景或配置变化立即刷新的自适应节奏，但不得降低首次识别响应。

### R8 — 发布与兼容

- 保持现有稳定版本发布语义，不新增预发布版本。
- 稳定期之前，性能采集结果形成报告，不设置新的 CI 硬门禁。
- 保持现有设置和校准数据兼容；任何存储标识变更必须有显式迁移。
- 保留 Room 能力，为下一任务的用户音频导入、校验和迁移模型提供结构化元数据存储；当前任务不得删除 Room 依赖。
- 移除 SessionViewModel 启动时对内置音色元数据的无意义写库，内置音色继续由 BuiltInKits 提供。

## Acceptance Criteria

- [ ] 连续 20 次进入/退出演奏页及切换性能档位后，分析线程和 CameraX 回调数量不持续增长。
- [ ] 应用后台停留 20 分钟再恢复，相机、手部识别、色块识别和声音均无需重启即可恢复。
- [ ] 切换扬声器、耳机或蓝牙音频路由时，Oboe 能自动恢复；失败时 2 秒内进入可发声的降级后端。
- [ ] 校准点不变时，GridProjection 不重复计算；绘制和单次击打定位不逐格创建 Mat。
- [ ] TAP 模式只有 TapHitProcessor 一条击打入口，现有连续击打与跨颜色快速切换回归通过。
- [ ] SequenceState 为不可变快照；虚拟时钟测试证明节拍处理时间不会形成累计漂移。
- [ ] 用户选择 HIGH 后触发运行时 LOW，限制解除能恢复 HIGH，且持久化首选值没有被覆盖。
- [ ] 应用启动不再向 Room 重复写入内置音色元数据，且现有内置音色选择和播放不受影响。
- [ ] Debug 单元测试、Lint、必要的 connected tests 和签名 Release 构建通过。
- [ ] 高/中/低三档设备完成实际演奏 FPS、分割耗时、缓存年龄、击打到出声、20 分钟稳定性、温升和后台恢复记录。
- [ ] 优化前后报告使用同一场景和配置，能定位收益或说明没有收益；无数据支持的复用优化不合入。

## Out of Scope

- 更换手部识别模型或色块识别算法。
- 改变默认击打阈值、冷却、抬手重置或现有音色映射。
- 大版本依赖升级、引入 Hilt 或新增跨模块架构层。
- 在当前内测阶段新增性能硬门禁。
- 在当前任务中实现音频文件选择、导入、转码、校验或用户音色管理界面；这些属于紧随其后的独立开发任务。

## Decision

- 当前任务完成后将开发用户音频文件导入、校验和迁移模型。
- 保留 Room 依赖，但不原样沿用当前仅保存内置音色摘要的模型。
- Room 负责音色包、音频资产、鼓垫映射、校验状态和迁移版本；音频文件本体存放在应用专属文件目录，不存数据库 BLOB。
- 详细方案见 `research/audio-import-storage-and-migration.md`。

## Notes

- 当前任务只解除 SessionViewModel 与 Room 的启动耦合，不提前实现下一任务的数据模型，避免扩大本轮稳定性优化范围。
- 实施必须按阶段提交，每个阶段通过独立质量门后再进入下一阶段。
